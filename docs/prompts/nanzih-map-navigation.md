## 1. 街景地圖改成高雄市楠梓區的真實街道

**目標**：街景模式的城市，從虛構的棋盤城市換成依照高雄市楠梓區真實道路網建出來的地圖。騎在裡面時，路名、路型、路口位置、河川、公園、學校和車站都和真實世界對得上。

### 圖資來源與授權

- 使用 **OpenStreetMap**（OSM）的真實圖資，範圍約為楠梓區中心：
  - 經度 120.285–120.335，緯度 22.705–22.745，約 5 × 4.4 km。
  - 涵蓋楠梓火車站、楠梓舊市區、右昌、後勁、德民路商圈、高雄大學、楠梓加工出口區（楠梓科技園區），以及後勁溪和楠梓溪。
- OSM 是 ODbL 授權，必須標示 **「地圖資料 © OpenStreetMap 貢獻者」**：
  - 遊戲畫面的地圖上要顯示。
  - README 要寫。
  - 資料檔的檔頭要寫。
- 只能使用 OSM 圖資，不可以使用 Google 地圖或街景的資料或截圖。

### 資料處理（離線、可重現）

- 寫一支匯入腳本 `scripts/osm/import-nanzih.py`：把下載的 `.osm` 圖塊轉成精簡的 TypeScript 資料檔 `src/data/cities/nanzih/`，並把處理流程寫進說明文件。
- 道路：
  - 保留可以騎的道路：`primary`、`secondary`、`tertiary`、`unclassified`、`residential`、`living_street` 和各種 `_link`。
  - 排除：國道（`motorway`）、步道、`service`、地下道（`tunnel`）。
  - 每條路記錄：路名、等級、寬度（有 `lanes` 就用車道數推算，沒有就依等級推定）、單行道。
- 把道路拆成 **路網圖**：
  - 節點是路口。
  - 邊是兩個路口之間的路段折線。
  - 只保留最大的連通網路。
- 座標：以範圍中心為原點，用等距投影換算成公尺，x 向東、z 向南（北方 = −z）。數值四捨五入到 0.1 m，減少檔案大小。
- 其他要匯入的資料：
  - 土地使用：住宅、商業、工業、公園／綠地、學校、水域和河川。
  - 地標：車站、捷運站、學校、醫院、公園、廟宇、便利商店、加油站，以及其他有名稱的 POI，含類別。
  - 有號誌的路口。
  - OSM 上已有的建築外框和樓層數。
- 資料檔要延遲載入（動態 `import()`），不能讓主程式包變大。

### 城市模型（domain，純 TS，可測試）

- 新的 `RoadNetwork`，包含：
  - 節點、路段、空間索引（格網）。
  - 查詢：最近路段、某點是道路／人行道／建築／水域／草地、所在路名、所在區域（里或地段名稱）。
- **建築**：
  - OSM 有外框的建築，就用真實外框和樓層數。
  - 其餘沿街面用固定 seed 的程式補上，風格依土地使用決定：
    - 住宅：台灣常見的 3～5 樓透天厝連棟。
    - 主要道路：5～12 樓的店面大樓。
    - 工業區：低矮的大廠房。
  - 補建時不可以蓋在道路、人行道、公園、學校、水域上。
- 碰撞：建築和水域是實心的。
- 道路寬度、人行道、地面和草地，都影響抓地力（沿用現有的路面係數）。
- 重生和 `R` 鍵：放到最近道路的右側車道，車頭沿著道路方向。
- 起點：楠梓火車站前。

### 車流（沿用規則，改走真實路網）

- 汽車沿路網的折線行駛，靠右，遵守單行道。
- 路口用曲線轉彎，轉彎前減速；跟車；會停下來讓玩家。

### 3D 呈現

- 沿用目前的擬真渲染：物理天空、PMREM、ACES、陰影、高解析程式貼圖。
- 道路：
  - 用世界座標貼圖的條帶網格，沿真實折線鋪設，路口重疊處不閃爍。
  - 標線：邊線、車道虛線、雙黃線。標線要在路口前斷開。
  - 有號誌的路口畫斑馬線，並放置真實位置的紅綠燈。
- 人行道和路緣石；河川用水面，公園用草地和樹，學校操場要畫出來。
- 建築：
  - 台灣街景元素：騎樓、鐵窗、冷氣、頂樓水塔、直立招牌。
  - 地標建築或區塊上方顯示名稱看板，例如車站和學校。
- 效能：依 250 m 區塊合併和剔除，目標桌機 60 fps。

## 2. 可展開的大地圖與導航

**目標**：像開放世界遊戲的地圖。小地圖可以展開成全螢幕大地圖，並且有完整的導航。

### 小地圖

- 會跟著車頭方向旋轉，可以切換成北方朝上。
- 顯示：真實路網（依道路等級分粗細和顏色）、水域、綠地、玩家、車流、導航路線、目的地。
- 在小地圖下方顯示目前的路名。

### 大地圖（按 `M` 或點小地圖開啟）

- 開啟時遊戲暫停，關閉後繼續。
- 操作：
  - 拖曳平移，滑鼠滾輪和 `+`／`−` 按鈕縮放。
  - 「回到我的位置」按鈕。
  - 手機可以用觸控拖曳。
- 顯示：
  - 道路（主要道路標出路名）、河川、綠地、學校、工業區。
  - 地標圖示，依類別分色。
  - 指北針、比例尺、圖例。
  - OSM 授權標示。
- 搜尋：輸入關鍵字，從地標和路名中找出結果，例如「高雄大學」「楠梓車站」「德民路」。點選結果就設為目的地。
- 地標列表：依類別篩選，例如車站、學校、公園、便利商店、加油站。
- 在地圖上點一下，就在最近的道路上放目的地圖釘。
- 設定目的地後，顯示路線、距離和預估時間，並提供「開始導航」「清除路線」按鈕。

### 導航

- 路徑規劃：
  - 在路網上用 **A\*** 找最短路線，遵守單行道。
  - 起點和終點可以在路段中間（從所在路段的兩端接上）。
- 逐路口指引（turn-by-turn）：
  - 依轉角角度產生「直行／靠左／左轉／迴轉／靠右／右轉」，也處理路名改變，以及「抵達目的地」。
  - HUD 上方的導航卡片顯示：箭頭圖示、「300 m 後右轉 德民路」、剩餘距離、預估抵達時間（ETA）。
- 偏離路線超過 25 m 就自動重新規劃；距離目的地 20 m 以內算抵達，顯示提示並結束導航。
- 3D 場景的路面上畫出半透明的導航路線帶，小地圖和大地圖也畫出路線。

## 3. 選車依車種和排氣量分類

**目標**：選車時，可以依「車種」和「排氣量」找車和比較。

- 在 `BikeSpec` 新增 `segment`（車種）欄位，每台車都要填，並通過 Zod schema 驗證：
  - 速克達：通勤速克達、運動速克達、復古速克達、大型速克達（大羊）。
  - 檔車：仿賽跑車、街車、復古檔車。
- 排氣量級距（在 domain 層由排氣量推導，和牌照對應）：
  - 125 cc 以下
  - 126–250 cc（白牌）
  - 251–550 cc（黃牌）
  - 551 cc 以上（紅牌）
- 選車卡片牆（賽道模式、對手、街景模式共用）：
  - 第一排篩選「車種」（全部、各車種），第二排篩選「排氣量」。
  - 結果依排氣量分段，每段有標題並註明台數，段內依排氣量和馬力排序。
  - 卡片徽章顯示車種和牌照，例如「運動速克達・白牌」。
- 模擬器的下拉選單：
  - 先選速克達或打檔車。
  - 車款用排氣量級距分組（`optgroup`），每個選項附上排氣量和車種。
- 要有元件測試：篩選和分組正確、選取正確。

## 品質要求

- 遵守分層規則：UI 只能從 domain `import type`，UI 不能 import data；需要的東西由 application 轉出。
- 單元測試（domain）：
  - 路網建立。
  - 最近路段、路面判斷。
  - A\* 正確，且遵守單行道。
  - 轉向指引的角度判斷。
  - 偏離後重新規劃、抵達判斷。
  - 車流在路網上行駛不出界。
  - 車種和排氣量級距的分類。
- UI 元件測試：大地圖的搜尋和設目的地、導航卡片、選車篩選。
- E2E：
  - 街景模式的煙霧測試改成楠梓地圖。
  - 開啟大地圖，搜尋地標，開始導航，HUD 出現導航指引。
- lint、typecheck、單元測試、build、E2E 全部通過；單檔不超過 300 行。
- 更新 README 和 `docs/PHYSICS.md`，包含 OSM 授權標示和資料更新方式。
